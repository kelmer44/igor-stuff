# Spanish floppy executable unpacker

A dependency-free C++11 prototype derived from the original executable's observed word transform and decompression routines. The library reads caller-provided bytes and returns an unrelocated resident image. It does not execute game code, start DOS, use Unicorn, write files, or include any game resource bytes. The command-line demonstration writes a new output file only when explicitly given an output path and refuses an existing output file.

## Supported input

Only the verified Spanish floppy `IGOR.EXE`: 39,537 bytes, CRC32 `8edcfa28`. Other files and altered/truncated inputs are rejected. Support for other executable revisions requires verifying their packing parameters separately.

## Build and use

Put the three source files in the same directory, then run:

```sh
c++ -std=c++11 -Wall -Wextra -Werror igor_floppy_unpack.cpp igor_unpack_main.cpp -o igor-unpack
./igor-unpack /path/to/original/IGOR.EXE resident-image.bin
```

The library API is `IgorUnpack::unpackSpanishFloppyExe()` in `igor_floppy_unpack.h`.

## Verified behavior

The result is 120,864 bytes. All output bytes match the memory image generated by the original unpacker immediately before native relocations, starting at linear address `0x10100` in the reference probe. Output SHA-256: `7c9d1050e554af2380231feb7c06720d8e11049d933d07cd82541bdcea517d3f`.

Tests compiled with AddressSanitizer and UndefinedBehaviorSanitizer passed: full-image comparison with the independent Unicorn reference, eight truncation lengths, a corrupted input, and null input. No sanitizer errors occurred.

The native word transform subtracts the preceding transformed word and rotates the result left by one bit. The subsequent decoder reads interleaved control words and literal/match bytes, with length and distance coding taken from the executable's own decompression tables. Segment-refresh markers are normalized to a contiguous image. Trailing relocation metadata is checked, but relocation adjustments are not applied: resource offsets remain independent of DOS load addresses.

The original runtime later modifies some bookkeeping fields. Those changes are deliberately absent from this static image; the asset bytes are available before that runtime initialization.

## Integration status

This is a standalone prototype, not yet integrated into the ScummVM fork. Integration needs:

- Adapt the library to ScummVM containers and error handling.
- Add a source identifier to the offset/size dictionary so entries can address DAT or the unpacked EXE image.
- Use the existing `loadData()` entry point to access either source through the same dictionary lookup.
- Establish all native text extents and numbering, then add the floppy Pascal-string decoding path.

The shipped code and dictionary contain algorithms and metadata only. The executable image is reconstructed exclusively from the user's original game file. No extracted game image is included with these deliverables.
